# Mutators in the battle room

The host chooses the mutators. **Mutators** is one of the battle room's
own on and off buttons, with the OA stamp, directly above **Select Map**
and as large as it, and opens the same picker a skirmish uses. It reads
**Mutators: off**, no lamp lit, while the room has none, and **Mutators: 2
on**, its green lamp lit, while it plays two; its red lamp lights while a
seated player lacks one. Resting the pointer on it shows a card that lists
them in the order they apply. While a launch locks the host's options,
**Mutators** is greyed and opens nothing. How the picker works, including
**USE THESE** and **CANCEL**, is
[Playing with mutators](../playing-with-mutators.md).

**Mutators** opens on the room's set. When the room has none, it opens
on the last set the host started a battle-room game with, already on.
Only the host's machine remembers that set, and only when **START**
really starts the match. **USE THESE** makes the set the room's.
**CANCEL** leaves the room's list as it was.

A guest sees that list and cannot change it. Where the host's button
stands, a guest has the same on and off button: **Mutators: 2 on**, or
**Mutators: off** while the host plays none. Its lamp is green once this
machine has built the host's list, red while one is missing, and unlit
with no set. A press on it, Return or the controller's Y opens the picker
read-only. Its hint is "The host's mutators. Only the host can change
them." The footer is **CLOSE**. Resting the pointer on the button shows
the card, a missing one reading "{name}: not installed", and "Click to
read.".

Anything this machine does not have is named in the chat: "*** You do not
have {name}. GET MUTATORS downloads it from {registry}." With several it
reads "*** You do not have {names}. GET MUTATORS downloads it from
{registry}." Only the first sentence is posted when no registry you use
offers it, when downloads from that registry are off, or when the
catalogue has not been read yet. Left of the button, **GET MUTATORS**, a
button in the room's own art, downloads the host's release, in the host's
order. While one is arriving a bar in the room's green fills there. A stop
shows "{name}: {problem}" and **GET MUTATORS** again. A mutator no
registry you use offers reads "{name}: not offered.", and downloads that
are off read "{registry}: downloads off." Those lines are in the room's
own lettering. Once this machine has every one, nothing stands beside the
button. **READY** waits: beside **START** a line reads "Ready once {name}
is here".

Every player's chat posts the change, including a guest who arrives in a
room that already has a set. Turning a set on posts "*** {host} turned on
mutators: {list}". Every change from none to some then posts "*** This
game is Open Annihilation only, and unranked." Turning them off posts
"*** {host} turned mutators off." On the host's machine only, a player
who does not have one, or who has another release, is named: "*** {player}
does not have {name}."

The rules dot marks any player whose mutators do not yet match the host's:
still receiving the list, still building, a build that failed, a different
result, or a player who has not named mutators. A seated player on Total
Annihilation 3.1c has no dot. The presence card's **Mutators** row lists
each one: "{item} ✓" when that player has the host's release, or, in
amber, "{item}: not installed" or "{item}: another release here". Under
that, an amber line says "Different from the host: no {name}." or
"Different from the host: another release of {name}." and "The game
cannot start until {player} gets it, or the host turns it off." The
host's own card marks every mutator ✓ and has none of those lines.

The host's **START** stays grey while any of those waits stands. While a
seated player lacks one, the line beside **START** reads "Waiting for
{player}: {name}". Pressing **START** as a difference appears asks "The
game did not start" on the host's machine only. Its paragraph is
"{player}'s mutators gave a different result from yours, so the game
would play differently on each machine." The amber line names the
mutator. When that player has the host's release and built a different
result, it is "{name}: release {here} here, release {there} on
{player}'s machine.", the host's release in both places. When that player
does not have the host's release, it is "{name}: {player} does not have
it.": a guest's machine tells the host that it has another release or
none, never which other one. A paragraph then says "{player}'s GET
MUTATORS button fetches release {release}." with the host's release,
when a registry the host's machine uses offers that release and downloads
from it are on. Every release the question names is the one the host
plays. **OK** is its only button.

A player already seated on Total Annihilation 3.1c cannot play the room.
Every machine posts "*** {player} plays Total Annihilation 3.1c, which
cannot play with mutators." and **START** stays grey while that player is
seated. While the room has mutators, the host also refuses a 3.1c player
who tries to join, and every Open Annihilation machine posts "*** {player}
plays Total Annihilation 3.1c and cannot join a game with mutators." Each
machine posts these lines in the language it shows, and a line wider than
the chat goes on in a further line.

A room with mutators is Open Annihilation only. Core Prime lists a game
with mutators for fun, outside the rankings. A mutator's Rules line in the Library says "Changes the
game: unranked on Core Prime".

The base game and the expansions are compared as
[Content in the battle room](content.md) describes. A map the host has
and a guest does not is still **GET MAP**.
